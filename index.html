Engineering approach

Architecture should make delivery easier, not make diagrams prettier.

I like clear boundaries, explicit contracts, strong tests, useful CI and measurable performance. I use AI coding tools extensively, but generated code still needs evidence, review, security and maintainable design.

Pragmatic modernizationImprove legacy systems incrementally without creating a rewrite-shaped business risk.
Evidence over confidenceTests, observability and CI should make technical claims verifiable.
Complexity has a budgetDDD, CQRS and distributed systems are tools, not personality traits.
Product is part of engineeringPerformance, accessibility, SEO and maintainability matter as much as the happy-path feature.
